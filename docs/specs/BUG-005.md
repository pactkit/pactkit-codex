## Background

After STORY-009 removed OpenCode/Classic deployment code, the codebase should only target Codex CLI. However, a comprehensive audit reveals **46 occurrences** of `.claude` across 13 source files. While the deployer's `_render_prompt()` and string replacement handle some of these at deploy time, many references exist in **runtime code** (skill scripts, CLI, config) that execute directly in the Codex environment where `.claude/` directories do not exist.

### Impact by Category

| Category | Count | Files | Severity | Issue |
|----------|-------|-------|----------|-------|
| **A. Skill scripts (runtime)** | 18 | visualize.py(14), board.py(2), scaffold.py(2) | P0 | Scripts run in Codex env — `.claude/` dirs don't exist. Causes missed config lookup, broken staleness checks, wrong default paths |
| **B. Deployer replace logic** | 8 | deployer.py | OK | Intentional `.claude/` → `.codex/` substitution at deploy time |
| **C. CLI help text** | 6 | cli.py(3), profiles.py(3 docstrings) | P2 | Help says `default: ~/.claude` but actual default is `~/.codex` |
| **D. Prompt template text** | 7 | commands.py(5), rules.py(1), skills.py(1) | P1 | Relies on deployer replace to catch all — fragile |
| **E. Other code logic** | 7 | adapter.py(1), doctor.py(1), config.py(1), scripts.py(1), profiles.py(3) | P1 | Dead code referencing classic/opencode, or wrong defaults |

## Root Cause

The codebase was forked from PactKit which supports three formats (classic, opencode, codex). STORY-009 removed the deployment functions but did not audit the full codebase for residual `.claude` references in:
- Standalone skill scripts (executed directly, not through deployer's replace pipeline)
- CLI argument help strings
- Config discovery logic
- Docstrings and comments that could mislead developers
