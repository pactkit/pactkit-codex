# BUG-001: Codex FormatProfile Incorrectly Marks commands_dir=None

| Field | Value |
|-------|-------|
| ID | BUG-001 |
| Status | Done |

## Background

Codex CLI supports custom slash commands via `~/.codex/prompts/*.md` files. However, the Codex `FormatProfile` in `profiles.py` sets `commands_dir=None` and `has_custom_commands=False`, which incorrectly signals that Codex has no command capability. While `_deploy_codex_prompts()` works around this by writing to `prompts_dir` directly, the profile metadata is misleading and could cause downstream consumers (e.g., `if profile.has_custom_commands`) to skip Codex command logic.

## Root Cause

The FormatProfile was designed when Codex CLI's command support wasn't fully researched. Codex's prompts ARE its commands — there is no separate concept.

## Requirements

### R1: Set `has_custom_commands=True` for Codex profile (MUST)

The Codex `FormatProfile` in `profiles.py` MUST set `has_custom_commands=True` since Codex CLI supports slash commands via `~/.codex/prompts/`.

### R2: Set `commands_dir` to point to prompts directory (MUST)

`commands_dir` MUST be set to `"~/.codex/prompts"` (same as `prompts_dir`) since in Codex, prompts and commands are the same concept.

### R3: Update any conditional logic that checks `has_custom_commands` (MUST)

Search all code for `has_custom_commands` usage and verify Codex is not incorrectly excluded.

## Acceptance Criteria

### AC1: Profile metadata is correct

- **Given** `get_profile("codex")`
- **When** inspecting `has_custom_commands` and `commands_dir`
- **Then** `has_custom_commands` is `True` and `commands_dir` is `"~/.codex/prompts"`

### AC2: Existing deployment still works

- **Given** the updated profile
- **When** running `_deploy_codex()` on a temp directory
- **Then** all 19 E2E tests (STORY-008) still pass
