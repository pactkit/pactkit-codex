# BUG-004: Package Name Collision — pactkit-codex Uses Same Package Name as pactkit

| Field | Value |
|-------|-------|
| ID | BUG-004 |
| Status | Done |
| Priority | P0 (Impact 5 / Effort 3) |
| Release | 0.1.0 |

## Background

The pactkit-codex project uses `pactkit` as its Python package name (`src/pactkit/`, `import pactkit`, CLI entry point `pactkit`). This directly collides with the upstream PactKit package (`pip install pactkit`) which is actively installed on development machines. When both are on `sys.path`, Python imports the wrong one, causing runtime failures.

## Root Cause

The project was forked from the PactKit repository and the package name was never changed. The `src/pactkit/` directory, all internal imports, `pyproject.toml` name, and CLI entry point all still reference `pactkit`.

## Requirements

### R1: Rename Python package directory (MUST)

Rename `src/pactkit/` to `src/pactkit_codex/`. All subdirectories and files move with it.

### R2: Update all internal imports (MUST)

All `from pactkit import ...` and `import pactkit...` statements in source and test files MUST be changed to `from pactkit_codex import ...` / `import pactkit_codex...`.

### R3: Update pyproject.toml (MUST)

- `name = "pactkit-codex"`
- `packages = ["src/pactkit_codex"]`
- `pactkit-codex = "pactkit_codex.cli:main"` (CLI entry point)
- All `[tool.ruff.lint.per-file-ignores]` paths updated

### R4: Update deployer.py sys.path manipulation (MUST)

The deployer has explicit `sys.path.insert()` logic referencing directory structure. This MUST be updated for the new package path.

### R5: Update keywords and URLs for Codex (SHOULD)

Replace Claude/Anthropic-specific keywords with Codex/OpenAI equivalents. Update project URLs.

### R6: All 92 tests pass after rename (MUST)

The full test suite MUST pass with zero failures after the rename.

## Acceptance Criteria

### AC1: No `import pactkit` anywhere in source

- **Given** the renamed codebase
- **When** `grep -r "from pactkit\b" src/ tests/unit/ tests/e2e/`
- **Then** zero matches (only `pactkit_codex`)

### AC2: CLI entry point works

- **Given** the package installed in dev mode
- **When** running `pactkit-codex version`
- **Then** prints version string

### AC3: All tests pass

- **Given** the renamed codebase
- **When** `pytest tests/unit/ tests/e2e/`
- **Then** 92+ tests pass

### AC4: No collision with upstream pactkit

- **Given** both `pactkit` and `pactkit-codex` on sys.path
- **When** `import pactkit_codex`
- **Then** imports the codex package, not upstream pactkit
